### 2. Beginner-Level Inconsistencies

1. **Category Revenue Discrepancy (Data vs. Output):**
   * Actual data from `sales_data.csv` (and calculated by `analysis.py`):
     * **Electronics:** 50,410 EGP
     * **Home:** 17,200 EGP
     * **Office:** 12,660 EGP
   * In both `build_powerpoint.py` (slide 5) and `sales_dashboard.html` (chart dataset), the numbers are hardcoded as **Electronics: 47,710 EGP** and **Office: 15,360 EGP** (a 2,700 EGP misattribution).
2. **Missing Files in `README.md` File Index:**
   * `README.md` lists 7 files under `## Files`, omitting newly added artifacts (`build_powerpoint.py` and `sales_dashboard.html`).
3. **Hardcoding Instead of Dynamic Ingestion:**
   * `build_powerpoint.py` and `sales_dashboard.html` rely entirely on manually transcribed values rather than dynamically reading and aggregating `sales_data.csv`. This manual entry caused the category revenue error above.
4. **Missing SQL DDL / Runner Script:**
   * `analysis.sql` queries a `sales_data` table using SQLite functions (`strftime`), but provides no `CREATE TABLE` DDL or SQLite database file/loader script for someone to run the queries out of the box.

1. **Dynamically Aggregate CSV in `build_powerpoint.py` (via GitHub Web / Mobile Browser):**
   * Edit `build_powerpoint.py` in the GitHub web interface to read `sales_data.csv` directly with `pandas` or Python's standard `csv` module. Calculating the slide metrics programmatically automatically eliminates transcription errors like the category revenue mismatch.
2. **Deploy `sales_dashboard.html` via GitHub Pages:**
   * Enable GitHub Pages in repository settings pointing to the portfolio directory (or add an `index.html` redirect). This provides a live, interactive mobile-friendly dashboard URL for recruiters without needing Power BI Desktop.
3. **Create an Interactive Cloud Notebook via Google Colab:**
   * Add a Google Colab notebook (`.ipynb`) link with an "Open in Colab" badge in `README.md`. From a phone, tablet, or lightweight browser, this enables running both Python aggregations and SQLite queries (using Python’s built-in `sqlite3` to load `sales_data.csv`) entirely on free cloud compute.
