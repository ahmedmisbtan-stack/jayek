### 1. Data-Analysis Portfolio Files Present

All portfolio assets are located in the `portfolio/` directory under `portfolio/sales-analysis/` (guided by `portfolio/GEMINI_AGENT_SPEC.md`):

* **Dataset:**
  * `sales_data.csv` — 25-row beginner practice dataset covering Jan–Mar 2026 across 7 columns (`Date`, `City`, `Category`, `Product`, `Units`, `Unit_Price_EGP`, `Revenue_EGP`).
* **Code & Analysis Scripts:**
  * `analysis.py` — Python script using pandas for data integrity assertions (row count, no nulls, revenue calculation check) and summary aggregations (by month, category, city, product).
  * `analysis.sql` — SQLite queries computing KPI totals and aggregations by month (`strftime`), category, city, and product.
  * `build_powerpoint.py` — Automation script using `python-pptx` to generate a 9-slide portfolio presentation deck (`sales_analysis_portfolio.pptx`).
* **Dashboards & Design Wireframes:**
  * `sales_dashboard.html` — Standalone responsive HTML dashboard using Chart.js to visualize KPIs and charts.
  * `sales_dashboard_reference.svg` — Static SVG wireframe/mockup illustrating the intended Power BI layout.
* **Documentation & Guides:**
  * `README.md` — Project overview, dataset context, baseline summary metrics, and file listing.
  * `NOTES.md` — Learner notes, analysis workflow, and future learning goals.
  * `POWER_BI_GUIDE.md` — Power BI import instructions, visual cards, and DAX measures.
  * `POWER_BI_DESIGN.md` — Style guidelines, color palette, and layout structure.

### 2. Beginner-Level Inconsistencies

1. **Category Revenue Discrepancy in `build_powerpoint.py`:**
   * In `sales_data.csv` (and calculated by `analysis.py`), category revenues are:
     * **Electronics:** 50,410 EGP
     * **Home:** 17,200 EGP
     * **Office:** 12,660 EGP
   * In `build_powerpoint.py` (slide 5), the values are incorrectly hardcoded as **Electronics: 47,710 EGP** and **Office: 15,360 EGP** (a 2,700 EGP mismatch).
2. **Incomplete File Index in `README.md`:**
   * The `## Files` section lists only 7 files, omitting `build_powerpoint.py` and `sales_dashboard.html`.
3. **Hardcoding Rather Than Dynamically Ingesting Data:**
   * Both `build_powerpoint.py` and `sales_dashboard.html` use manually hardcoded metric values rather than dynamically reading `sales_data.csv`. This manual data duplication directly introduced the category revenue error.
4. **Standalone SQL Without DDL or Database Setup:**
   * `analysis.sql` assumes an existing `sales_data` table, but includes no `CREATE TABLE` / schema definition or SQLite setup instructions for someone testing the SQL queries.

### 3. Three Practical Improvements (Without a Desktop Computer)

1. **Dynamically Ingest CSV in `build_powerpoint.py` (via GitHub Web / Mobile Browser):**
   * Update `build_powerpoint.py` directly using GitHub’s web editor to load `sales_data.csv` (using Python’s built-in `csv` module or `pandas`) and calculate totals dynamically. This eliminates manual transcription errors without local setup.
2. **Host `sales_dashboard.html` via GitHub Pages:**
   * Enable GitHub Pages in repository settings pointing to the portfolio folder (or add a top-level redirect). This turns the HTML file into a live, interactive web dashboard accessible to reviewers from any mobile browser or tablet.
3. **Add a Google Colab / Cloud Notebook Badge:**
   * Add a Google Colab link in `README.md` that pulls `sales_data.csv`, loads it into Pandas and an in-memory SQLite database (`sqlite3`), and executes the queries. This allows recruiters and learners to interactively run the full Python and SQL workflow on free cloud infrastructure from a phone or tablet.
